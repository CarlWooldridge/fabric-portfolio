Plain OPTIMIZE
○DEFERRED 		OPTIMIZE dbo.table File count/size — bins small files together Manual, or auto compaction Faster — fewer files to open None on regular writes Yes — always Default target ~1GB, tuned for large tables. Adaptive target file size scales this down for smaller tables like yours. Idempotent.
Z-Order
○DEFERRED 		OPTIMIZE dbo.table
ZORDER BY (col1, col2)		 Row placement — co-locates similar values across filter columns Manual, part of OPTIMIZE Faster multi-column filtered queries (file skipping) None on regular writes Yes Named for the Z-order space-filling curve — genuine geometry reference. Best when queries filter 2+ columns together.
V-Order
◆PER-WRITE 		OPTIMIZE dbo.table VORDER
or table property / session default		 Internal file encoding — sorting, row-group layout, dictionary encoding Automatic on every write once enabled; or forced via OPTIMIZE Faster reads, esp. Direct Lake/Power BI (~10–50% for Spark) ~15% slower on every write while enabled Yes, at write time Required for Direct Lake to perform well. Disabled by default in new workspaces (write-heavy default). "V" likely nods to VertiPaq/Verti-Scan — unconfirmed.
Liquid Clustering
○DEFERRED 		Table property clusterBy + OPTIMIZE Row placement, like Z-Order but reconfigurable later Manual OPTIMIZE required to actually cluster Faster filtered reads via file skipping None on regular writes Yes, on OPTIMIZE only Regular writes do NOT cluster data — easy to forget and end up stale. More flexible than Z-Order — can change keys without redefining partitions.
OPTIMIZE FULL
■ONE-OFF 		OPTIMIZE dbo.table FULL Full reclustering of every file, including previously-clustered ones Manual, deliberate Restores full clustering benefit after a strategy change High — can rewrite most/all of a large table Yes, all files Requires runtime 2.0 (Delta 4.2). Use only after changing clustering keys/provider — not routine maintenance.
Fast Optimize
▽TUNING 		SET spark.microsoft.delta.
optimize.fast.enabled = TRUE		 Smarter bin selection — skips compaction unlikely to help Session-level, applies during any OPTIMIZE Same benefit as plain OPTIMIZE Lower — fewer unnecessary rewrites Only bins likely to benefit Not compatible with Z-Order or liquid clustering. Tunable via minNumFiles, parquetCoefficient.
Auto Compaction
◆PER-WRITE 		SET spark.databricks.delta.
autoCompact.enabled = TRUE
or table property		 File count/size, same target as plain OPTIMIZE Automatic, triggered right after each write Same as plain OPTIMIZE, continuously maintained Small added cost on writes that trigger it Yes, when triggered The production answer to "won't a re-run undo this?" — stops your Copy activity table from re-fragmenting on every reload.
onCheckpointOnly mode
▽TUNING 		SET spark.microsoft.delta.
autoCompact.onCheckpointOnly.
enabled = TRUE		 Reduces overhead of auto compaction's own fragmentation checks Session-level, modifies auto compaction No direct read impact Lowers per-commit overhead N/A — tuning only Requires runtime 2.0 (Delta 4.1). Defers evaluation to checkpoint commits (~every 10) instead of every write.
File-level compaction targets
▽TUNING 		SET spark.microsoft.delta.
optimize.fileLevelTarget.
enabled = TRUE		 Prevents re-compacting files that already met a prior target size Session-level, modifies OPTIMIZE No direct read impact Reduces write amplification Fewer files touched Not on by default — Microsoft recommends enabling it.
VACUUM
○DEFERRED 		VACUUM dbo.table
[RETAIN n HOURS]		 Physically deletes old file versions no longer part of current table state Manual, separate from OPTIMIZE No benefit to current queries Storage cleanup, not query optimization Deletes, doesn't rewrite Default retention 7 days. This is what your Dataflow Gen2 table needs — old overwrite versions still sitting there.
Reading the matrix: ○ deferred techniques cost nothing until you invoke them — the "put data anywhere, clean up later" model. ◆ per-write techniques cost something on every write, continuously, in exchange for never letting the problem accumulate. ■ one-off is a deliberate, infrequent operation. ▽ tuning settings don't optimize anything themselves — they change how another technique behaves.
